## 0. 方案摘要

### 0.1 一句话方案

复用智能运维系统的 Tauri 2 桌面壳与 Vue 3 + Ant Design Vue 前端，删掉主机/巡检/报告业务页面；Go 引擎作为 sidecar，开发期监听 `127.0.0.1:54310`，打包后由 `--port 0` 动态分配端口并经 `ENGINE_PORT` 回传宿主，提供 `/api/v1` JSON 接口，用 SQLite 存题库、答题记录与统计；前端新增题库、练习、考试、错题本、统计五个业务模块；Excel/CSV 导入题目与图片，导入前可做工作表/表头/列映射并支持整批撤销；服务端种子化洗牌实现题目/选项乱序，用选项规范键（canonical key）保证乱序后仍可正确判分，并在组卷时为每题写入快照，保证题目后续编辑不影响历史复核。

### 0.2 关键决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D-01 | 桌面壳使用 Tauri 2，不引入 Electron/Wails | 与现有项目一致，安装包小、内存占用低；前端和窗口控制代码可直接复用 |
| D-02 | 复制智能运维系统的单包前端与 Tauri 壳，删除巡检业务页面 | 该项目是 `src/` + `src-tauri/` 的单包结构，无 workspace 链；复制后改菜单/路由即可，改造成本低于引入 Vben monorepo |
| D-03 | 题库引擎使用 Go 标准库 `net/http`，不引入 Gin | 题库引擎是新写；Go 1.22+ 方法路由足够，减少依赖。前端契约只看 JSON 与 HTTP，不依赖具体框架 |
| D-04 | 数据库用 SQLite（`modernc.org/sqlite`，纯 Go） | 单机免安装、单文件备份；纯 Go 驱动可保持 `CGO_ENABLED=0`，不影响打包链路 |
| D-05 | 保留前端 auth store 与 `X-Token` 拦截器，改为“本机静默会话” | 复用现有请求封装与路由守卫；用户无登录负担；真正的边界是仅监听回环地址 |
| D-06 | API 响应包裹沿用 `{code:0,message,data}` | 智能运维系统的 axios 拦截器按 `code===0` 判成功；沿用可零改动复用 `request.ts`，只有 `code!==0` 才是业务错误 |
| D-07 | 答案存规范选项键（A/B/C…），乱序只改展示顺序 | 乱序后判分不用反查文本；历史记录不受题干编辑影响 |
| D-08 | 组卷、题目顺序、选项顺序都由服务端种子化生成并落库 | 断点续答、考试恢复、结果复核看到的是同一份试卷 |
| D-09 | 导入采用“预览 token + 确认提交”两阶段 | 先暴露行级错误和重复项，避免脏数据直接进库 |
| D-10 | 开发期引擎 54310、前端 54311；打包后引擎动态端口 | 与智能运维系统的 5501/5502 隔离，两个项目可同时运行；生产用 `--port 0` + `ENGINE_PORT` 避免端口冲突 |
| D-11 | 数据目录 `%APPDATA%\com.quizbox.desktop` | 与 Tauri `app_data_dir` 一致，安装目录只读也能正常工作 |
| D-12 | 答题会话按批加载题目（每批 50 题） | 万题题库一次性下发会拖垮 WebView；批次加载兼顾自由跳题与性能 |
| D-13 | 建考试时把题目内容写入 `exam_answers.snapshot_json`；练习不存快照，实时读库 | 考试一旦发布，之后编辑或软删除题目都不影响已交卷的判分与复核；练习则保持“题目即最新”的轻量语义 |
| D-14 | 导入题目记录 `import_job_id`，批次可撤销 | 误导入可整批回滚；撤销只软删除本批次题目，历史快照不受影响 |
| D-15 | 导入预览支持工作表、表头行、列映射，并可重映射 | 真实 Excel 表头不固定、列顺序不一致；同一 token 重新解析后再提交 |
| D-16 | 每日、导入前、迁移前自动备份；恢复走重启标记 | 单机数据只有一份；数据库运行中不能自我替换，恢复必须退出引擎后执行 |
| D-17 | 引擎提供一次性令牌的正常关闭接口 | 避免宿主直接 kill 造成 WAL 未检查点、导入事务中断 |
| D-18 | 记录智能运维系统基线提交并冻结依赖 | 不跟随上游升级，保证依赖可解析、构建可复现 |
| D-19 | 答题卡超过 200 题启用虚拟滚动，单次会话上限 5,000 题 | 万题题库仍可全量练习，但 DOM 数量与单次写库量保持可控 |

### 0.3 非目标（首版不做）

- 账号体系、多用户、班级/角色权限、局域网或公网部署（架构预留，见第 14 节）。
- 主观题、填空、判断、连线、程序题；首版仅单选、多选（图片是题目/选项的媒体属性，不是题型）。
- 富文本题干、公式编辑器、Word 原样排版导入。
- 云同步、多端进度同步、AI 出题、间隔重复算法。
- 多选题部分得分（首版全对才得分）。

## 1. 需求

### 1.1 用户与场景

| 场景 | 描述 |
| --- | --- |
| 建库 | 用户新建“数据结构”“网络工程师”等题库，按知识点打标签 |
| 导题 | 从 Excel 模板批量导入题目，图片按文件名自动关联；先预览错误再入库 |
| 顺序练习 | 按题库顺序刷题，答完即时看对错与解析 |
| 乱序练习 | 随机抽 20/50/全部题，题目和选项均可打乱；中途退出后下次继续 |
| 模拟考试 | 按题库/标签抽 50 题，限时 60 分钟，交卷后统一判分 |
| 复习错题 | 自动收集错题，连续答对 2 次后自动移出待复习列表 |
| 看统计 | 查看总正确率、按题库/标签的正确率、最近 30 天趋势 |

### 1.4 验收基线

- 导入一份 500 行的带图 Excel，预览能列出错误行；提交后题库题目数与成功行数一致，图片正常显示。
- 同一份题库以“题目乱序 + 选项乱序”建立练习，关闭应用重开后，题目与选项顺序不变，已答状态保留。
- 50 题、60 分钟考试：倒计时结束自动交卷，得分与手工核算一致；未答题按错处理。
- 答错 3 题后错题本出现 3 条；连续答对 2 次后从“待复习”消失。
- 统计页正确率与直接用 SQL 统计结果一致。
- 表头顺序打乱、列名使用别名的 Excel 能在映射步骤正确导入；缺少必填列时阻止提交并指出缺哪一列。
- 导入批次撤销后，题库题目数与列表恢复到导入前；已产生的历史成绩仍可查看。
- 每日首次启动生成自动备份；从备份恢复并重启后，题库、图片、历史记录与备份时一致。
- 5,000 题答题卡滚动与题号跳转流畅；单次会话超过上限时有明确提示。
- 关闭应用时引擎正常退出，无遗留进程；进行中的导入任务在下次启动被标记为失败而非永久 running。
- 断网状态下应用内外功能均可用；杀掉引擎进程后前端有明确错误提示并可重试。

## 2. 总体架构

### 2.1 运行时拓扑

```text
┌──────────────────────────── Tauri 2 主进程（Rust） ───────────────────────────┐
│  主窗口 1200×800（最小 1080×720）/ 无边框 / 托盘 / 单实例 / 生命周期管理       │
│                                                                              │
│  setup: 检查恢复标记 -> 拉起 sidecar(externalBin) -> 读取 ENGINE_PORT         │
│         -> 端口就绪 -> 显示窗口                                               │
│  exit : 请求引擎正常关闭 -> 等待 3 s -> 兜底 kill                            │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │ http://127.0.0.1:<动态端口>
┌───────────────────────────────▼───────────────┐      ┌───────────────────────┐
│ WebView2                                       │ HTTP │ Go Engine             │
│ Vue 3.5 + Ant Design Vue 4.2                   │◄────►│ 标准库 net/http       │
│ （页面、路由、状态、窗口控制）                  │ JSON │ /api/v1               │
└───────────────────────────────────────────────┘      │ /api/v1/images/*      │
                                                       │ SQLite (WAL) + 文件   │
                                                       └───────────┬───────────┘
                                                                   │
                                              %APPDATA%\com.quizbox.desktop\
                                                quiz.db / images / backups / logs
```

开发期前端经 Vite 代理访问固定端口 54310；打包后由 sidecar 动态分配端口，前端通过 Tauri 命令 `engine_base_url` 获取，不写死端口。

### 2.2 进程与生命周期

1. Tauri `setup` 读取 `app_data_dir()`；若存在 `restore.pending.json`，先按恢复流程处理完再启动引擎。
2. 通过 `tauri-plugin-shell` 以 sidecar 方式拉起 `engine`：`--host 127.0.0.1 --port 0 --data-dir <app_data_dir>`，`CREATE_NO_WINDOW` 隐藏控制台。
3. 引擎监听成功后向 stdout 输出 `ENGINE_PORT=<n>`；Rust 读取该行并写入 `EngineState`，最多等 10 s。成功或超时都显示窗口，超时由前端展示“引擎启动失败 + 诊断”。
4. 前端 `initApiBase()` 调用 Tauri 命令 `engine_base_url` 获取 `http://127.0.0.1:<port>/api/v1`；随后 `GET /health` 校验 `app == "quizbox"`。
5. 退出（关闭窗口或托盘退出）时先 `POST /system/shutdown` 带一次性令牌，最多等 3 s；超时或失败再 `child.kill()`，SQLite 依靠 WAL 兜底。
6. 第二个实例启动时由 `tauri-plugin-single-instance` 激活已有主窗口后退出，避免拉起第二份引擎。

### 2.3 模块职责

| 模块 | 目录 | 职责 |
| --- | --- | --- |
| Tauri 壳 | `src-tauri/` | 窗口、托盘、单实例、引擎拉起/回收 |
| 前端应用 | `src/` | 页面、路由、状态、API 调用、答题交互（Vue 3 + AntD 单包） |
| HTTP API | `engine/internal/api/` | 路由、鉴权中间件、参数校验、响应包裹、静态资源与 SPA 托管、智能答疑 SSE 代理（按接入方式分派） |
| 鉴权 | `engine/internal/authx/` | 随机会话 token 生成、密码散列校验 |
| 存储层 | `engine/internal/store/` | SQLite 打开、内嵌迁移、CRUD、判分、统计查询；题目/题库/练习/考试模型都在这里 |
| 导入器 | `engine/internal/importer/` | XLSX/CSV 解析、表头探测与列映射、答案归一化、预览与错误报告 |
| 导出器 | `engine/internal/exporter/` | 题库导出 xlsx、导入模板生成 |
| 图片 | `engine/internal/api/images.go` + `store/images.go` | 校验、SHA-256 命名、落盘去重、按名取流 |
| 智能答疑 | `engine/internal/bicqa/` | BIC-QA 客户端，以及两种接入方式共用的按用户配置读写 |
| ima 网页版 | `engine/internal/imaweb/` | ima 私有 CGI 客户端：Cookie 鉴权、建会话、流式提问、`code 41` 登录失效映射 |
| 流式解析 | `engine/internal/aistream/` | 厂商无关的 SSE 分帧与宽松字段提取，统一成 `delta` / `thinking` / `error` / `done` |
| 响应与日志 | `engine/internal/response/` | 统一包裹与错误码；日志同时写文件与内存环形缓冲（诊断页读取） |

### 3.4 本机静默会话

保留前端的 `auth` store、`X-Token` 拦截器和路由守卫，但去掉登录页：

1. 引擎 `POST /api/v1/auth/login` 接受 `{username:"local"}`（密码可为空），仅在回环来源下签发本机 token；返回 `{token, username:"local"}`。token 存 SQLite `sessions` 表，重启不失效。
2. `main.ts` 顺序固定为：`await initApiBase()` → `app.use(createPinia())` → `setActivePinia(pinia)` → `await ensureLocalSession(pinia)` → `app.use(router)` → `mount`。
   - 已有 `quiz-token`：先 `GET /auth/me` 校验；401 则重新静默登录。
   - 无 token：调用 `authApi.login('local','')`，写入 `quiz-token` / `quiz-user`。
   - 失败：显示全屏“本地服务未启动”，提供重试按钮，不挂载路由。
3. `api/request.ts` 的 401：跳过登录接口本身；清除 token；调用一次静默登录；重放原请求一次；仍失败提示“本地服务连接失败”。不再跳转 `#/login`。
4. 删除 `views/login/index.vue`、`/login` 路由与守卫里的登录重定向；守卫只保留“无 token 时尝试静默登录，失败则停留错误页”。

> 实现注意：`ensureLocalSession(pinia)` 显式传入 pinia 实例，内部用 `useAuthStore(pinia)`，避免在 `app.use(pinia)` 之后、组件外调用时出现 “no active Pinia”。该方法不得调用 `useRouter()`，因为此时 router 尚未安装。

> 该 token 不是安全边界，只是复用前端会话结构。真正的边界是仅监听 `127.0.0.1` 且为单机应用；未来若开放局域网，必须恢复密码登录并默认拒绝弱口令。

## 4. 数据设计

### 4.1 实体关系

```text
banks 1 ─── n questions 1 ─── n question_options
                    │
                    ├── n question_tags n ── 1 tags
                    └── 0..1 wrong_book（按用户，主键 user_id + question_id）

banks 1 ─── n import_jobs 1 ─── n questions（import_job_id，可整批撤销）

users 1 ─── n practice_sessions 1 ─── n practice_answers（按 session_id + question_id）
users 1 ─── n sessions
users 1 ─── n banks（个人题库 owner_id；owner_id 为 NULL 表示公共题库）

exams 1 ─── n exam_attempts 1 ─── n exam_answers（快照 + 作答）

images：questions.stem_image / question_options.image 存 filename（内容寻址）
exam_answers.snapshot_json：建卷时的题目快照，判分与复核只读快照
```

与早期设计稿的差异：练习与考试不再共用 `attempts` 表——练习是 `practice_sessions`（按用户、实时读题干），考试是 `exams` + `exam_attempts`（按学号、读快照），两套记录互不影响。

### 4.2 建表 SQL（SQLite）

当前 `user_version = 8`，由 `engine/internal/store/migrations/0001–0008` 按序执行；引擎用 `embed` 把迁移脚本编进二进制，启动时按版本号逐个应用并在事务内推进 `user_version`。下表是各脚本的职责，DDL 即实际执行的内容：

| 脚本 | 内容 |
| --- | --- |
| `0001_init.sql` | 会话与设置：`sessions`、`settings` |
| `0002_exams.sql` | 题库与题目基础表 + 考试：`banks`、`questions`、`question_options`、`exams`、`exam_attempts`、`exam_answers`（`user_version = 2`） |
| `0003_imports.sql` | 导入批次：`import_jobs`，`questions` 增加 `import_job_id`（`user_version = 3`） |
| `0004_accounts.sql` | 账号与归属：`users`，`sessions` 增加 `user_id`，`banks`/`exams` 增加 `owner_id`（`user_version = 4`） |
| `0005_practice.sql` | 练习与错题：`practice_sessions`、`practice_answers`、`wrong_book`（`user_version = 5`） |
| `0006_images.sql` | 题图：`images` 表，`question_options` 增加 `image` |
| `0007_practice_resume.sql` | 续练与范围：`practice_sessions` 增加 `status`/`finished_at`/`last_seq`/`scope_json`/`shuffle_options`/`option_orders_json`/`marked_json`/`duration_sec`/`bank_name_snapshot`，`practice_answers` 增加 `time_spent_ms`（`user_version = 7`） |

**`0002_exams.sql`**

```sql
CREATE TABLE IF NOT EXISTS banks (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT    NOT NULL,
  description TEXT    NOT NULL DEFAULT '',
  is_deleted  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT    NOT NULL,
  updated_at  TEXT    NOT NULL
);

CREATE TABLE IF NOT EXISTS questions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  bank_id      INTEGER NOT NULL REFERENCES banks(id),
  type         TEXT    NOT NULL CHECK (type IN ('single','multiple')),
  stem         TEXT    NOT NULL,
  stem_image   TEXT,
  answer       TEXT    NOT NULL,
  analysis     TEXT    NOT NULL DEFAULT '',
  difficulty   INTEGER NOT NULL DEFAULT 2 CHECK (difficulty BETWEEN 1 AND 5),
  source       TEXT    NOT NULL DEFAULT '',
  sort_order   INTEGER NOT NULL DEFAULT 0,
  content_hash TEXT    NOT NULL,
  is_deleted   INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT    NOT NULL,
  updated_at   TEXT    NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_questions_bank ON questions(bank_id, is_deleted);
CREATE INDEX IF NOT EXISTS idx_questions_sort ON questions(bank_id, is_deleted, sort_order, id);

CREATE TABLE IF NOT EXISTS question_options (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
  key         TEXT    NOT NULL CHECK (length(key) = 1),
  content     TEXT    NOT NULL DEFAULT '',
  sort_order  INTEGER NOT NULL DEFAULT 0,
  UNIQUE (question_id, key)
);

CREATE INDEX IF NOT EXISTS idx_options_question ON question_options(question_id, sort_order);

CREATE TABLE IF NOT EXISTS exams (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  title              TEXT    NOT NULL,
  bank_id            INTEGER NOT NULL REFERENCES banks(id),
  question_ids_json  TEXT    NOT NULL,
  total_count        INTEGER NOT NULL,
  time_limit_sec     INTEGER NOT NULL,
  open_at            TEXT    NOT NULL,
  close_at           TEXT    NOT NULL,
  password_salt      TEXT    NOT NULL,
  password_hash      TEXT    NOT NULL,
  token              TEXT    NOT NULL UNIQUE,
  status             TEXT    NOT NULL DEFAULT 'published'
                             CHECK (status IN ('published','closed')),
  shuffle_questions  INTEGER NOT NULL DEFAULT 1,
  shuffle_options    INTEGER NOT NULL DEFAULT 0,
  created_at         TEXT    NOT NULL,
  updated_at         TEXT    NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_exams_status ON exams(status, created_at);

CREATE TABLE IF NOT EXISTS exam_attempts (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  exam_id        INTEGER NOT NULL REFERENCES exams(id) ON DELETE CASCADE,
  name           TEXT    NOT NULL,
  student_no     TEXT    NOT NULL,
  token          TEXT    NOT NULL UNIQUE,
  status         TEXT    NOT NULL DEFAULT 'ongoing'
                         CHECK (status IN ('ongoing','submitted')),
  started_at     TEXT    NOT NULL,
  deadline_at    TEXT    NOT NULL,
  submitted_at   TEXT,
  score          REAL,
  correct_count  INTEGER NOT NULL DEFAULT 0,
  answered_count INTEGER NOT NULL DEFAULT 0,
  total_count    INTEGER NOT NULL,
  UNIQUE (exam_id, student_no)
);
```

### 4.3 数据不变量

1. `questions.answer` 与 `practice_answers.chosen_json` 始终是**规范选项键**的 JSON 数组（升序去重）；展示字母由 `practice_sessions.option_orders_json` 中的乱序映射推导。
2. `option_orders_json` 结构为 `{"<questionId>": ["C","A","D","B"]}`，值是那一道题全部选项键的一个排列；乱序关闭时为空对象。
3. `questions.type` 只有 `single` / `multiple`；单选 `len(answer) == 1`，多选 `len(answer) >= 2`，答案键必须都存在于 `question_options`。判断题按单选存储（A=正确、B=错误）。
4. 题目、题库均为软删除（`is_deleted = 1`），历史练习与考试记录仍能关联原题；选项内容允许编辑，历史判分以当时写入的 `is_correct` 为准。
5. 考试进行中，接口永远不返回未答题目的答案与解析；交卷后才通过 `ExamResult` 下发。
6. 图片以 SHA-256 命名，同一内容只存一份；数据库只存 filename，不存绝对路径。
7. 时间统一存 UTC ISO-8601 字符串，前端按本地时区显示。
8. `practice_answers` 只记录已判分的题，主键 `(session_id, question_id)`；同一题重复提交返回首次结果，不覆盖、不重复计数。
9. `exam_answers.snapshot_json` 在创建考试时写入后不可修改，结构为 `{id,type,stem,stem_image,options,answer,analysis}`；判分、下发与结果复核都读快照。快照中的 `answer` 只用于服务端判分与交卷后展示。
10. `practice_sessions.last_seq` 与 `exam_attempts` 的 `deadline_at` 都属于“进度/计时”字段：`last_seq` 落在 `1..total_count`，只记录位置不参与判分；倒计时一律以服务端 `deadline_at` 为准。
11. `questions.sort_order` 只影响列表与顺序练习的先后：导入按文件行序写入，手工新建取同题库 `max(sort_order)+1`；按题序练习按 `(sort_order, id)` 升序取候选。`scope_json` 保存本次练习的筛选条件与 `rangeStart/rangeEnd`，是旧练习记录能正确回显题序范围的唯一来源。
12. `questions.import_job_id` 只指向已完成的导入批次；撤销批次把该批次题目置 `is_deleted=1` 并写 `import_jobs.reverted_at`，不物理删除，也不影响 `exam_answers.snapshot_json`。
13. `wrong_book` 主键 `(user_id, question_id)`：答错 `wrong_count+1`、`correct_streak` 归零；答对 `correct_streak+1`，达到阈值（默认 2）置 `mastered=1`。
14. `users.is_disabled` 为预留字段，当前版本没有禁用账号的接口；`users.username` 唯一且 `COLLATE NOCASE`，`local` 为保留名。
15. 数据恢复以 `restore.pending.json` 为唯一标记：标记存在时引擎拒绝写入业务数据（403），由宿主完成替换后清除标记再启动；恢复前必须再生成一份 `pre-restore` 备份。

## 5. 核心流程与算法

### 5.1 组卷采样

练习与考试是两条不同的组卷路径：练习**不存快照**，题目内容实时读 `questions`；考试在建卷时把题目内容写成 `exam_answers.snapshot_json`，之后改题库不影响已发布的考试。

**练习（`POST /practice/sessions`，实现见 `store.CreatePracticeSession`）**

```text
输入：bankIds、questionIds、count、order(fixed|random)、source(bank|wrong)、
      questionType、difficulty、tags[]、shuffleOptions、startSeq、endSeq
1. 归一化：source 非 wrong 一律按 bank；单个 bankId 并入 bankIds；difficulty=0 表示不限。
2. 拼筛选条件 practiceScope（与 CountPracticeCandidates 共用）：
   q.is_deleted=0；source=wrong 时改为 wrong_book JOIN questions 且 mastered=0；
   bankIds/questionIds 用 IN；标签按名称匹配、多个标签取 OR；题型、难度按需追加。
3. 题序范围：offset = startSeq-1，span = endSeq-startSeq+1；
   startSeq≤1 视作从头，endSeq=0 或小于 startSeq 时不限结束位置。
4. 排序：order=fixed → ORDER BY q.sort_order, q.id；order=random → ORDER BY RANDOM()。
5. 取数：LIMIT = min(count, 5000)，有 span 时再与 span 取小；offset>0 追加 OFFSET；
   实际取 limit+1 条即可判定 truncated。
6. 候选为空：offset>0 时返回 400「起始题号 N 超出范围（当前筛选共 M 道）」，否则「没有符合条件的题目」。
7. shuffleOptions=true 时逐题生成选项顺序写入 option_orders_json；展示字母统一从 A 开始重排。
8. 事务写 practice_sessions：question_ids_json、scope_json、total_count、order_mode、last_seq=1。
```

- `scope_json` 存本次筛选条件与 `rangeStart/rangeEnd`，是旧练习记录回显题序范围的唯一来源；旧记录为 0/0 表示不适用。
- 练习的题号就是数组下标 + 1，不落库；跳题、答案卡都以这个序号为准。
- 同一会话内题目不重复（`question_ids_json` 去重后写入）。

**考试（`POST /exams`）**

按题库抽 `count` 道题，把 `{id,type,stem,stem_image,options,answer,analysis}` 快照写进 `exam_answers`，`exams.question_ids_json` 只留题目 id 顺序。之后编辑题干、选项、答案或软删除题目，都不会改变已发布考试的展示与判分；题目被删时结果页照常读快照。

### 5.2 题目与选项乱序

**展示字母重排**：接口返回的每个选项包含 `key`（规范键，判分用）和 `label`（展示字母，A–H）。

```text
规范选项：A=甲, B=乙, C=丙, D=丁
option_order = ["C","A","D","B"]
展示：label A -> key C（丙）
      label B -> key A（甲）
      label C -> key D（丁）
      label D -> key B（乙）
正确答案 ["A"] -> 展示为 B
```

- 前端只用 `label` 渲染、只提交 `key`；用户无法从前端推断原始答案位置。
- 题目下发时，题干、选项、图片在练习中实时取自 `questions`，在考试中取 `exam_answers.snapshot_json`；再按 `option_orders_json` 生成 `label`。
- 练习判分返回的是**规范键**（前端按本次 `option_orders_json` 换算 label 回显）；考试交卷返回 `ExamResult`，`chosenLabels`/`answerLabels` 已由服务端换算好。
- 练习页有“选项乱序”开关（默认值来自设置），建练习时一次性生成并写入 `option_orders_json`；考试创建时可分别选择打乱题目与选项顺序。乱序结果落库，刷新或继续不会重新洗牌。

### 5.3 判分

```go
func Grade(q Question, chosen []string) bool {
    if len(chosen) == 0 {
        return false
    }
    ans := ToSet(q.Answer)      // 规范键
    pick := ToSet(chosen)
    if len(ans) != len(pick) {
        return false
    }
    for k := range pick {
        if !ans[k] {
            return false
        }
    }
    return true
}
```

- 单选：服务端强制 `len(chosen) <= 1`；多选允许只选一个（判错），但提交时前端要求至少选一个。
- 练习判分读 `questions.answer` 的**当前值**（练习不存快照，改答案会影响未完成的练习）；考试判分读 `exam_answers.snapshot_json.answer`，保证已发布考试的答案不受题库改动影响。
- 多选全对才得分，无部分分。
- 未作答按 0 分处理；练习中未作答不写 `chosen`，判分时视为错（若调用提交）。
- 考试得分 = `round(correct / total * 100, 1)`；结果页同时显示答对数与总题数。
- 交卷幂等：已交卷的考试再次 `submit` 返回首次结果；练习重复提交已判分的题返回既有结果。过期后的考试作答请求返回 400（`40000` + 中文原因）。

### 5.4 练习流程

1. 前端在练习设置页选题库（可多选）、来源（题库 / 错题本）、题型、难度、标签与题量；拖动「题序范围」时先调 `POST /practice/preview` 取当前筛选的可用题数 `candidates`，用于提示上限与「接着上次往下练」的起点。
2. 点「开始练习」→ `POST /practice/sessions`，引擎按筛选条件组卷并**一次性返回全部题目**（单次上限 5000，取不够时 `truncated=true`），跳转 `/attempts/{id}/play`。
3. 单选：点选项立即 `POST /practice/sessions/{id}/answers`，服务端判分并返回答案、解析与错题统计；选项锁定。
4. 多选：勾选后点“提交本题”再提交；未选时按钮禁用。
5. 每次作答更新 `answeredCount`、`correctCount`、`lastSeq`；答错写入或更新错题本，连续答对达阈值（默认 2 次）自动移出。
6. 切题时 `POST .../position` 只记录 `seq` 与 `marked[]`，不判分；刷新或关闭后用 `GET /practice/sessions/{id}` 恢复题目、已答、标记与位置。
7. 已判分的题再次提交返回既有结果，不覆盖、不重复计数（幂等）。
8. 点“完成练习” → `POST .../submit`，状态置 `finished`，返回 `PracticeSummary`；未作答按错统计但不进错题本。

题序范围（`order=fixed` + `source=bank` + 未指定 `questionIds` 时生效）表示在筛选结果有序列表中取第 `startSeq` 到第 `endSeq` 道（1 基、含两端），落库在 `scope_json` 里，`PracticeSession.rangeStart/rangeEnd` 回传给前端显示，旧记录为 0/0 表示不适用。

练习「时长」用各题 `timeSpentMs` 之和，避免用户中途离开导致虚高；单题计时上限 30 分钟。

### 5.5 考试流程与计时

主机端：

1. `POST /exams` 按题库抽题生成考试（时长、时间窗、可选密码、可选打乱题目与选项），题目以快照写入，返回 `token`。
2. 分享链接为 `http://<IP>:<端口>/e/<token>`；桌面端在「考试」页一键复制链接并可申请防火墙放行，服务端部署用 `PUT /share` 配置公网域名。
3. `GET /exams/{id}/attempts` 查看参与名单：姓名、学号、状态、得分、交卷时间。
4. 考试 `status` 由时间窗实时计算：未发布或已过期 → `closed`，未到开始时间 → `not_open`，其余 `open`。

参与者：

5. 打开 `GET /e/{token}` → 内嵌移动端答题页；先 `GET /api/public/exams/{token}` 取标题、题量、时长、时间窗、是否需要密码。
6. 填姓名、学号、密码后 `POST .../start`，返回 `state=ongoing`、`attemptToken`、`deadlineAt`、`remainingSec` 与全部题目；该学号已交卷时直接返回 `state=submitted` 与成绩。
7. 选项变更后防抖调用 `POST .../answers` 落库；考试期间不下发答案与解析。刷新页面用 `GET .../attempt?attemptToken=` 续答。
8. 倒计时以服务端 `deadlineAt` 为准，前端本地计时只用于展示；到 0 秒自动 `POST .../submit`。
9. 交卷幂等，重复提交返回首次结果；`UNIQUE(exam_id, student_no)` 防止同一学号重复交卷。
10. 交卷后才在响应里返回 `ExamResult`（含正确答案、你的作答、解析与逐题对错），`GET .../result?attemptToken=` 可再次查询。

题干与选项取自创建时的快照，之后修改题库不影响进行中的考试。关闭窗口时宿主先请求引擎正常关闭（见 9.2），答案已防抖落库，正常关闭不丢最近一次保存。

### 5.6 导入流程

```text
预览阶段

     file（≤20 MB）、images[]（≤300 张，单张 ≤8 MB、合计 ≤100 MB）、
     可选 options（JSON 字符串：{sheet, headerRow, mapping}）
  2. 按扩展名分派：.xlsx/.xlsm 走工作簿解析，.csv 按文本读取；
     旧版 .xls 与 zip 包直接拒绝，并提示另存/解压后再导入
  3. xlsx：列出全部工作表，在前 10 行里探测最可能的表头，按表头别名生成初始列映射；
     自动挑选标题命中最多的那张表
  4. 若必填字段没映射上，前端在弹窗里改工作表/表头行/列映射后，
     **重新上传同一个文件并带上 options**——没有独立的 remap 接口，服务端也不留存原始文件
  5. 解析 1–20000 行，逐行校验并归一化（题型、答案、难度、标签），计算 content_hash
  6. 随包图片当场入库（SHA-256 去重），按小写文件名建“原文件名 → filename”映射，
     替换题干图片列里的本地引用；没匹配到文件的只记警告，不阻断导入
  7. 先与库内同题库未删除题目按 hash 查重，再与文件内已出现过的行查重
  8. 返回 token、统计、前 5 行样例、前 200 条错误、映射结果与警告
  9. 预览结果只驻留内存（pendingImports[token]），2 小时过期、绑定题库，进程重启即失效

提交阶段
 10. POST /banks/{id}/imports {token, policy}
 11. token 不存在/过期/与题库不符 → 400 提示重新上传；token 取用即删，不能重复提交
 12. 先创建 auto/pre-import 备份，**备份失败直接取消本次导入**
 13. 同步执行：500 行一个事务写 questions/question_options/tags；
     sort_order 取文件行序，import_job_id 指向本批次
 14. 行级失败不中断整体，累计 inserted/skipped/failed，错误明细写 import_jobs.errors_json
 15. 返回 ImportOutcome，前端刷新题库统计与批次列表

撤销
 16. POST /imports/{id}/revert：仅完成未满 7 天、未撤销、且本批次题目未被手动编辑
     （updated_at = created_at）的批次可撤销
 17. 撤销把本批次题目置 is_deleted=1，写 import_jobs.reverted_at，返回撤销/跳过题数
```

- 采用“部分成功”策略：合法行入库，错误行进报告，避免一行错误导致整批失败。
- `policy`：`skip` 跳过与库内/文件内重复的题，`keep` 仍导入；预览阶段的 `duplicate` 按 skip 口径统计。
- 错误明细以 CSV（UTF-8 带 BOM）提供下载，列为“行号、错误原因”，内容取自 `import_jobs.errors_json`。
- 列映射的键固定为 `type/stem/answer/analysis/difficulty/tags/source/stem_image/option_A..option_H/option_image_A..option_image_H`（见 §6），值为列字母。
- 工作表默认取识别结果，可手工指定；表头行默认自动探测，可改为 1–20 行。
- 题图缺失只记警告，题目照常入库（图片字段为空），可在编辑页补传。
- xlsx 内的浮动图片无法可靠定位到题目行，检测到只记警告并给出数量，提示导出为图片文件后随包上传。
- 导入内容不执行任何 HTML/公式；CSV 以文本读取，`= + - @` 开头的单元格按字符串保存，防公式注入。
- 撤销是软删除，不物理删除，历史作答记录不受影响。

### 5.7 错题本规则

> 规则已确认（2026-10-30），以下为最终口径，不再作为待定项。

- **收集范围**：练习与考试使用同一套规则，只收集“已作答且判错”的题。练习在单题判分时写入；考试在交卷统一判分时写入。未作答（练习提前结束、考试到时交卷）按错计分，但**不进入错题本**。
- **答错**：`wrong_book` upsert — `wrong_count+1`、`correct_streak=0`、`last_wrong_at=now`、清空 `mastered_at`（已掌握的题再次答错会回到待复习）。
- **答对**：仅对已在错题本中的题累计 `correct_streak+1`；达到设置阈值（默认连续 **2** 次）写入 `mastered_at`。不在错题本中的题答对不创建记录。
- **待复习**：列表默认过滤 `mastered_at IS NULL`；已掌握可单独查看。
- **手动操作**：允许手动标记“已掌握”，也允许重置；重置清空 `mastered_at` 与 `correct_streak`，回到待复习。手动移除直接删除记录，之后再次答错按新记录从 1 开始计数。
- **重练**：以 `scope.question_ids` 建立练习，题目顺序随机，选项乱序沿用练习设置；重练结果按上述规则继续累计连续答对次数。
- **阈值设置**：`wrong_master_threshold` 默认 2，可在设置页调整；修改后只影响后续判分，不回算历史记录。
- **防重复计数**：练习同一题重复提交返回既有结果；考试交卷幂等，均不会重复累计 `wrong_count` 或 `correct_streak`。

### 5.8 统计口径

| 指标 | 口径 |
| --- | --- |
| 题目总数 | `questions` 中 `is_deleted = 0` 的数量（按可见题库） |
| 练习作答 | `practice_answers JOIN practice_sessions`，限本人，按 `answered_at` 落在时间窗 |
| 考试作答 | `exam_answers JOIN exam_attempts`，仅 `status='submitted'`；非管理员再按 `exams.owner_id` 过滤 |
| 总作答数 / 正确数 | 以上两者相加；正确率 = `correctTotal / answeredTotal` |
| 练习次数 | `practice_sessions` 条数（按 `created_at` 落在时间窗） |
| 考试次数 / 平均分 | `exam_attempts` 中 `status='submitted'` 的条数与 `avg(score)` |
| 日趋势 | 练习按 `answered_at`、考试按 `submitted_at` 各归到本地日期后合并；`all` 从最早一天补到今天 |
| 标签正确率 | `practice_answers → questions → question_tags` 聚合，一题多标签时分别计入 |
| 题库正确率 | 同上按 `questions.bank_id` 聚合，只统计作答过的题 |
| 概览：今日答题 / 待复习 | `overview` 按 `practice_answers.answered_at` 的本地日期统计；待复习取 `wrong_book.mastered = 0` |

时间窗取值：`7d`（默认，含今天共 7 天）、`30d`、`all`（不限起点）；非法值按 `7d` 处理。

### 5.9 备份与恢复

**自动备份触发点**

| 触发 | 文件名 | 说明 |
| --- | --- | --- |
| 每日首次启动 | `auto/quizbox-daily-YYYYMMDD.zip` | 当天已存在则跳过；在迁移完成后、接受请求前执行 |
| 导入提交前 | `auto/pre-import-YYYYMMDD-HHmm.zip` | 降低误导入/撤销失败的风险 |
| 数据库迁移前 | `pre-migrate-<version>.zip` | 备份失败则中止迁移，保持旧版本可启动 |
| 手动 | `quizbox-YYYYMMDD-HHmm.zip` | 设置页“立即备份” |

- 备份内容：`VACUUM INTO` 生成的数据库快照、`images/`、`manifest.json`（应用版本、`user_version`、文件 SHA-256、创建时间）；不包含引擎二进制、日志、临时导入文件。
- 保留策略：每日 7 份、导入前 5 份、迁移前 3 份、手动不限；自动备份总量超过 2 GB 时从最旧开始删除。设置页可修改份数并立即清理。
- 备份是同步 IO，但 `VACUUM INTO` 只读快照，通常数百毫秒；导入前备份在任务开始前完成，不阻塞 HTTP 请求。

**恢复流程（不在运行中热替换）**

```text
1. 前端 POST /backups/{name}/restore
2. 引擎校验 zip 路径、manifest、版本兼容性与磁盘空间，写 restore.pending.json
   {backup, sha256, created_at, requested_at}，进入维护模式（写请求返回 403 + `40300`）
3. 前端提示“需要重启应用完成恢复”，用户确认后宿主调用正常关闭并重启
4. 宿主启动时先读 restore.pending.json：
   a. 校验备份 sha256，解压到 tmp/restore-<时间>/
   b. 用引擎 --verify-db <临时库> 做完整性检查与版本校验，失败则中止并保留现场
   c. 把当前 quiz.db* 与 images/ 移到 tmp/rollback-<时间>/，再原子替换为新数据
   d. 删除 restore.pending.json，启动引擎
5. 任一步失败：保留原数据与 rollback 目录，写 restore.error.log，正常启动旧数据并在界面提示
```

- 恢复前自动再生成一份 `pre-restore-<时间>.zip`，避免恢复错版本后无法回头。
- 备份 zip 只写数据目录；解压时拒绝绝对路径与 `..`，防止路径穿越。
- 备份包含做题记录等个人数据，设置页提示妥善保管，不上传任何位置。

### 5.10 外联考试（局域网链接）

**目标**：组织者把一场考试以链接形式发给同一局域网内的其他人，参与者用手机或电脑浏览器直接答题，成绩回收到主机端。

**流程**

```text
1. 主机端「考试」页新建考试：选题库、抽题数、时长、开考时间段、考试密码、是否打乱题目
2. 创建成功生成 32 字节随机 token，链接形如 http://<局域网IP>:<端口>/e/<token>
3. 参与者打开链接 → 填写姓名 + 学号 + 考试密码 → 开始答题
4. 首次进入时把选定题目快照写入 exam_answers（题干/选项/正确答案/解析）
5. 逐题作答，前端 300ms 防抖自动保存；关闭页面后凭本地 attemptToken 自动续答
6. 到达个人截止时间（开始时间 + 时长，且不晚于考试结束时间）或手动交卷 → 服务端判分
7. 参与者看到得分与逐题明细；主机端「成绩」抽屉看到全部参与者与得分
```

**约束与规则**

| 项 | 规则 |
| --- | --- |
| 身份 | 姓名 + 学号/工号；`UNIQUE(exam_id, student_no)` 保证同一场考试每人一条记录 |
| 重复进入 | 已交卷：直接返回既有成绩；答题中：续答并带回已保存答案；已超时：自动交卷后返回成绩 |
| 密码 | PBKDF2-HMAC-SHA256（12 万次迭代）加盐存储，仅校验不落明文 |
| 时间窗 | 不在 `open_at`–`close_at` 内拒绝开始；个人截止 = min(现在 + 时长, close_at) |
| 快照 | 组卷后题目、选项、答案、解析全部快照；考试期间修改题库不影响进行中的考试 |
| 判分 | 单选/多选均要求所选集合与正确答案完全一致；得分 = 正确题数 / 总题数 × 100，保留一位小数 |
| 幂等 | `submit` 重复调用返回已落库结果；答案保存覆盖式更新，超时保存返回“答题时间已结束” |
| 乱序 | 创建时 `ORDER BY RANDOM()` 抽题；`shuffle_questions` 记录该场是否乱序（选项乱序为 P1） |
| 关闭 | 主机端关闭考试后，公开接口返回“考试已关闭”，已进入的答题按截止时间正常结算 |

**网络**

- 桌面端 sidecar 以 `--host 0.0.0.0` 启动，端口动态分配；主机端通过 `GET /share` 拿到端口与全部局域网 IPv4 地址，拼接链接。
- 参与页为 Go 内嵌单文件 HTML（`engine/internal/api/web/e.html`），无外网 CDN 依赖，断网可用。
- 首次分享需在 Windows 防火墙放行引擎与主程序；界面提供「允许局域网访问」按钮，经 UAC 授权后添加程序级入站规则。
- 公网访问预留 `public_base_url` 设置：填写隧道/反向代理地址后链接优先使用该地址，引擎仍只监听本机端口。
- 主机端与参与者均不访问互联网；参与者只需能访问主机 IP 的该端口。

## 6. 导入规范

### 6.1 Excel/CSV 模板列

默认读取 `题目` Sheet、表头第 1 行；两者都可在预览的“映射”步骤覆盖。列顺序不敏感：按表头名识别，识别不出时由用户手动指定列。

| 列 | 表头 | 必填 | 说明 |
| --- | --- | --- | --- |
| A | 题型 | 是 | `单选`/`单选题`/`single`；`多选`/`多选题`/`multiple` |
| B | 题干 | 是 | 纯文本，≤ 5000 字；换行用 `\n` 或单元格内换行 |
| C–J | 选项A … 选项H | 至少两个 | 从 A 连续填写；允许 2–8 个选项；每个 ≤ 1000 字 |
| K | 答案 | 是 | 单选 `A`；多选 `AC`、`A,C`、`A、C`、`A C` 均可 |
| L | 解析 | 否 | ≤ 10000 字 |
| M | 难度 | 否 | 1–5，默认 2 |
| N | 标签 | 否 | 中英文逗号/顿号/分号分隔，最多 10 个 |
| O | 题干图片 | 否 | 图片文件名（不含路径），如 `tree.png` |
| P–W | 选项A图片 … 选项H图片 | 否 | 对应选项的图片文件名 |
| X | 来源 | 否 | 试卷/教材名称，≤ 200 字 |

`说明` Sheet 放填写示例与答案格式说明，导入时忽略。

表头别名（大小写、全半角、空格不敏感）：

| 字段 | 可识别表头 |
| --- | --- |
| 题型 | 题型、类型、type |
| 题干 | 题干、题目、试题、question、stem |
| 选项 | 选项A、A、选项1、optionA |
| 答案 | 答案、正确答案、answer |
| 解析 | 解析、答案解析、analysis |
| 难度 | 难度、difficulty、level |
| 标签 | 标签、知识点、tags |
| 来源 | 来源、出处、source |
| 图片 | 题干图片、图片、stem_image；选项A图片、optionA_image |

- 同一字段匹配到多列时报 E1013，由用户保留一列。
- 未知列直接忽略，不报错；必填字段（题型、题干、答案、至少一个选项）缺映射时报 E1012。

| 题型 | 题干 | 选项A | 选项B | 选项C | 选项D | 答案 | 解析 | 难度 | 标签 | 题干图片 |

### 6.3 解析与归一化

- 答案：转大写、去空白、全角字母转半角；按 `, ， 、 ; ； / 空格` 切分；去重、升序；再校验数量与存在性。
- 表头与数据区：以选定表头行为基准，向下读取连续数据行；完全空行跳过；连续 20 个空行视为数据结束，避免尾部格式或备注被误读。
- 列映射先按“字段 → 列号”取值，再做上述归一化；映射变化只影响后续解析，不修改原始文件。
- 内嵌图片：XLSX 中浮动图片不做自动行关联，检测到即记 W2004 并返回数量；数据仍可导入。
- 题型别名统一：`单选题/单选/single` → `single`；`多选题/多选/multiple` → `multiple`。
- 题干：去除首尾空白，连续空白折叠为单个空格（保留换行）；图片列只取文件名（去路径）。
- 选项：从 A 开始，遇到空选项即视为结束；中间空缺报错（E1007）。
- 标签：去重、去空、大小写不敏感合并（以首次出现为准）。
- 查重哈希：`sha256(type + "\n" + normalizedStem + "\n" + sortedNonEmptyOptions + "\n" + sortedAnswer)`；同题库内比较。

### 6.4 编码与文件限制

| 项 | 限制/规则 |
| --- | --- |
| XLSX | ≤ 20 MB，≤ 20,000 行；默认读 `题目` Sheet，可在预览中切换任意工作表，表头行可选 1–20 |
| CSV | ≤ 20 MB，≤ 20,000 行；UTF-8（含 BOM）优先，无 BOM 时尝试 GBK，仍失败报 E1011；表头行可选 1–20 |
| 图片 | 单张 ≤ 8 MB；`png/jpeg/webp/gif`；按文件头嗅探 MIME，不信任扩展名 |
| 单次图片数 | ≤ 3,000 张 |
| ZIP 导入包（P1） | `questions.xlsx` 或 `questions.csv` + `images/` + 可选 `manifest.json`；≤ 100 MB，解压总量 ≤ 500 MB |
| ZIP 炸弹 | XLSX 解压总量超过 200 MB 拒绝（excelize 读取前检查文件大小与行数） |

## 7. API 设计

> 本章按**当前实现**编写，与 `engine/internal/api/router.go` 逐条对齐（85 个 `HandleFunc` + 1 个静态兜底 `Handle`）。
> 早期设计稿中的 `/attempts/*`、`/wrong-book`、`snake_case` 字段、`409/300xx` 业务码均已废弃，
> 请以本章为准；新增接口时先改这里，再改代码。

### 7.1 通用约定

- **Base URL**：开发期 `http://127.0.0.1:54310/api/v1`；打包后 `http://127.0.0.1:<动态端口>/api/v1`，由 Tauri 命令 `engine_base_url` 下发，前端一律通过 `getApiBase()` 取，不写死端口。
- **响应包裹**：`{"code":0,"message":"ok","data":...}`。`data` 为空时整个字段被省略（`omitempty`），前端按 `data ?? null` 处理。
- **字段命名**：一律 **camelCase**（`bankId`、`stemImage`、`timeSpentMs`、`answeredCount`）。时间为 ISO-8601 字符串，前端本地化展示。
- **鉴权**：请求头 `X-Token: <token>`，不使用 `Authorization: Bearer`。会话 7 天过期，存 SQLite `sessions` 表，重启不失效。免 token 的路径只有：`/health`、`/ping`、`/api/v1/health`、`/api/v1/ping`、`POST /auth/login`、`POST /auth/register`、`GET /auth/captcha`、`GET /images/{filename}`、`/api/public/*`、`GET /e/{token}`，以及 `--web-dir` 托管的静态资源。
- **401 处理**：前端拦截器清 token → 静默重登一次 → 重放原请求；仍失败提示“本地服务连接失败”，不跳登录页。
- **分页**：`page`（从 1 开始，`page<1` 视为 1）、`size`（默认 20，最大 100，越界回落 20），返回 `{items,total}`。非分页列表只返回 `{items}`。
- **限流**（按 IP 或按用户，内存计数）：登录 10 次 / 5 分钟 / IP；注册 5 次 / 10 分钟 / IP；AI 提问 20 次 / 5 分钟 / 用户。超限返回 429 + `42900`。
- **维护模式**：`restore.pending.json` 存在时，除 `GET`/`HEAD` 与 `POST /auth/logout`、`POST /backups/restore`、`DELETE /backups/restore` 以外的请求返回 403 + `40300`，提示先重启或取消恢复。
- **图片**：接口只返回 `filename`，前端用 `resolveImageUrl(name)` 拼 `/images/{filename}`。文件名为 SHA-256 + 扩展名，响应带 `Cache-Control: public, max-age=31536000, immutable`，支持 `Range`。
- **静态托管**：配置 `--web-dir` 时 `GET /` 交给 `spaHandler`：命中文件直接返回（文本按 `Accept-Encoding` 现场 gzip），带扩展名但不存在返回 404，其余回退 `index.html`（hash 路由）。缓存头与压缩策略见 §10.2。
- **关闭接口**：`POST /system/shutdown` 不走 token 鉴权，改校验请求头 `X-Shutdown-Token`；引擎未拿到令牌时该接口返回 404（服务端部署默认不启用）。

#### 智能答疑（BIC-QA / ima 网页版）

两种接入方式**并存**，由用户在设置页自选，互不影响，切换时不清除另一方的凭据：

| `provider` | 上游 | 凭据 | 稳定性 |
| --- | --- | --- | --- |
| `bicqa`（默认） | `api.bic-qa.com` 官方 Open API v1 | API Key（`Authorization: Bearer`） | 官方契约，稳定 |
| `imaweb` | `ima.qq.com` 网页前端私有 CGI | 浏览器登录 Cookie | 逆向所得，随时可能变动 |

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /ai/config` | 用户 | `{provider,enabled,hasKey,keyMask,hasCookie,cookieMask,baseUrl,model,timeoutSec,ready}`，**永不回传明文 Key 与 Cookie** |
| `PUT /ai/config` | 用户 | `{provider,enabled,baseUrl,apiKey,cookie,model,timeoutSec,clearKey,clearCookie}`；`apiKey` / `cookie` 留空表示沿用已保存值，`clear*` 才清除 |
| `POST /ai/test` | 用户 | 按当前 `provider` 建一次会话验证连通与鉴权，35 秒超时 |
| `GET /ai/usage` | 用户 | 透传 BIC-QA 额度信息；`provider=imaweb` 时恒定返回 40000，ima 网页版没有额度接口 |
| `POST /ai/chat` | 用户 | SSE 流式问答，见 §7.3 |

`PUT /ai/config` 的几处约定：

- `provider` 只接受 `bicqa` / `imaweb`；缺省或无法识别一律按 `bicqa`，保证未写 `provider` 的旧配置文件继续可用。
- 切换 `provider` 且未显式传 `baseUrl` 时，仅当原地址等于旧接入方式的默认值才换成新默认值；用户自填的地址（例如走代理）保持不动。
- `cookie` 写入前会清洗：去掉 `Cookie:` 前缀、换行与多余空格——从开发者工具整行粘贴是常态。
- `cookieMask` 只回 `已保存 N 字符`，不暴露任何片段（Cookie 里常直接含账号令牌，比 API Key 更敏感）。

`ready` 按接入方式判定：`bicqa` 要求 `enabled && apiKey != ""`，`imaweb` 要求 `enabled && cookie != ""`。

配置按账号隔离存放：`<data-dir>/bicqa/user-<id>.json`（0600），不入库、不进备份。提问只带题干与选项，不含答案与解析；问题超过 4000 字自动截断。

ima 网页版的接口契约（逆向自前端 bundle，仅依赖三件最稳定的事实）：

| 用途 | 请求 | 失败表现 |
| --- | --- | --- |
| 建会话 | `POST /cgi-bin/session_logic/init_session`，`{"envInfo":{"robotType":10000,"interactType":2},"msgsLimit":10,"sessionType":0}` → `{code:0,sessionId}` | HTTP 200 + `{"code":41}` |
| 提问 | `POST /cgi-bin/assistant/qa`，`{"sessionId","robotType":10000,"question","questionType":1,"clientId":""}`，`Accept: text/event-stream` | HTTP 401 + 响应头 `Trpc-Func-Ret: 41` |

鉴权在参数校验之前返回（拿假 Cookie 会先得到 `code 41` 而不是参数错误），所以这两个参数组一旦被接受就说明结构正确。请求签名 `x-ima-cm` / `x-ima-ckey` / `x-ima-ctk` 只在客户端内置加密桥（`hasNativeBridge()`）下启用，纯网页 Cookie 鉴权不需要实现。`code 41` 统一映射为面向用户的「ima 登录已失效，请重新登录后复制新的 Cookie」，不把内部错误码抛给界面。

```http

{
  "bankIds": [1],
  "count": 20,
  "order": "fixed",
  "startSeq": 21,
```

```json
  "code": 0,
  "message": "ok",
  "data": {
    "session": {
      "id": 42, "bankId": 1, "bankName": "数据结构", "source": "bank",
      "totalCount": 20, "answeredCount": 0, "correctCount": 0,
      "status": "ongoing", "lastSeq": 1, "durationSec": 0,
      "order": "fixed", "shuffleOptions": true,
      "rangeStart": 21, "rangeEnd": 60,
```

**7）智能答疑流式问答**

```text
POST /api/v1/ai/chat
Content-Type: application/json

{ "question": "题干 + 选项", "conversationId": "", "title": "练习答疑", "mode": "brief" }
```

响应与上游无关，两种接入方式都归一化成同一组事件（`imaweb` 在 `meta` 帧里多带 `provider` 字段）：

响应 `Content-Type: text/event-stream`，逐帧推送：

```text
event: meta
data: {"conversationId":"c_88f2…","provider":"bicqa"}

event: thinking
data: {"text":"先看选项 A……"}

event: delta
data: {"text":"答案是 C。"}

event: done
data: {}
```

- `event` 取值：`meta` / `thinking` / `delta` / `error` / `done`；`error` 帧带 `{"message":"…"}`，随后必跟 `done`。
- 引擎在转发前统一拼接长度约束：`mode=brief`（默认）追加“不超过 200 字、先结论后逐项一句话”，`mode=full` 追加“逐一说明每个选项并补充知识点”。同一道复杂题，简答模式首字时间从约 70 秒降到 15 秒左右。
- 停止生成由前端中断 fetch 连接实现，引擎侧通过请求 context 取消上游。
- 必须逐帧 `Flush`，否则会被中间层攒批；`statusWriter` 已实现 `Flush` 透传，新增中间件时不要破坏。

```http

```

```json

```

写标记后，除白名单外的写请求一律 403，重启时由引擎替换数据库。

```text

```

令牌为空（服务端部署）时该接口直接返回 404，避免公网被误关。

### 7.4 错误码

实际只用了 HTTP 状态 + 一组固定 `code`，**不再有 300xx 业务码**，具体原因看 `message`：

| code | HTTP | 触发场景 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 40000 | 400 | 参数缺失、格式错误、业务校验失败（题目不在本次练习、密码长度、预览过期等） |
| 40100 | 401 | 未登录或会话过期（含 `X-Token` 缺失） |
| 40101 | 401 | 登录失败：用户名或密码错误 |
| 40300 | 403 | 无权限（他人题库、非创建者的考试、非管理员、恢复维护模式） |
| 40400 | 404 | 资源不存在，或未启用该接口（如服务端的 shutdown） |
| 42900 | 429 | 触发限流 |
| 50000 | 500 | 内部错误，详细信息写引擎日志，不回传调用方 |

状态冲突（重复交卷、考试已关闭、重复恢复）统一用 400 + `40000`，幂等接口重复调用返回首次结果而不是报错。

### 7.5 权限与可见性矩阵

| 对象 | 读 | 写（改/删/导入） | 备注 |
| --- | --- | --- | --- |
| 公共题库（`ownerId=null`） | 所有登录用户 | 仅管理员 | 只有管理员能创建公共题库 |
| 个人题库 | 归属人 + 管理员 | 归属人 + 管理员 | 他人访问返回 403 |
| 题目/标签 | 跟随所属题库 | 跟随所属题库；标签改名/合并/删除仅管理员 | 题目与标签无独立归属 |
| 练习会话 | 仅本人 | 仅本人 | 管理员不越权查看他人练习 |
| 考试 | 创建者 + 管理员 | 同左 | 参与者只能通过 token 访问自己的答题 |
| 用户列表/角色/重置密码 | 管理员 | 管理员 | `local` 账号受保护 |
| 设置、备份、诊断日志 | 管理员（设置读取放开给所有用户） | 管理员 | |
| 导入模板保存、题库导出写盘 | 本机（回环来源） | 本机 | 浏览器访问只能走下载接口 |

> 已知差异：管理员对题库、考试**没有归属过滤**，能看到所有用户的数据与考试名单；普通用户只能看到自己的练习与错题。

### 8.3 答题页交互规范

**布局**

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 退出  数据结构 · 随机练习      3/50   ⏱ 42:15   已保存   — □ ×     │ 48px

│ [题干图片，点击放大]                          │ 已答 3 / 未答 47     │
│ ┌ A 选项内容 ─────────────────────────────┐   │ ● 当前  ■ 已答       │
│ └─────────────────────────────────────────┘   │ ▲ 标记               │
│ ┌ B …                                     ┐   │                      │
│ …                                             │ [交卷/完成练习]      │
│ [提交本题]（多选）                            │                      │
│ ┌ 解析/答案（练习判分后） ────────────────┐   │                      │
│ └─────────────────────────────────────────┘   │                      │
└───────────────────────────────────────────────┴──────────────────────┘
```

**顶栏**

- 左侧：退出/暂停；标题；题型与题号。
- 中间：进度 `已答/总数`；考试显示倒计时（`HH:MM:SS`，最后 60 s 红色）。
- 右侧：保存状态（保存中/已保存/失败重试）、窗口控制（最小化/最大化/关闭）。
- 全屏页自带拖动区：顶栏用 `data-tauri-drag-region`，按钮、输入框等交互元素加 `data-no-drag`，与 BasicLayout 的顶栏一致。
- 窗口控制复用 `WindowControls.vue`，放在顶栏最右侧。

**选项**

- 单选：圆形单选控件 + 选项文本；点击即提交（练习）或选中待保存（考试）。
- 多选：方形复选 + “提交本题”按钮；未选时禁用。
- 选项含图片时：左侧 72×72 缩略图，点击预览，不阻塞选中。
- 判分后：正确项绿色实心边框 + 浅绿底；错选项红色边框；其他项降低透明度。
- 键盘：`1–8` 或 `A–H` 选择/切换；`Enter` 提交/下一题；`←/→` 上一题/下一题；`M` 标记。输入框不存在于答题页，避免快捷键冲突。

**答案卡**

- 题号网格，最多 50 列自动换行；当前题描边主色，已答实心绿，标记右上角琥珀点。
- 题量 ≤ 200 时直接渲染；超过 200 使用虚拟滚动：固定行高、只渲染可视区上下各 2 行，题号跳转与键盘切换自动滚入视野。滚动容器高度随窗口自适应，避免整页滚动。
- 顶部显示“已答 X / 总 Y”和当前题号输入框，输入回车跳题（超出范围时提示）。
- 点击跳题；练习已答题可回看但不可改；考试可随时改。
- 底部“交卷”按钮；考试点击后弹窗显示“未答 2 题，确认交卷？”；练习显示“完成练习”。

**续答与快照**

- 进入答题页先 `GET /practice/sessions/{id}`，一次性取回题目、已答、标记与 `lastSeq`，直接渲染到上次位置（练习题量上限 5000，不分批）。
- 切题时异步上报 `last_seq`（失败不影响作答，下次保存答案时一并更新）。
- 练习结果复用本次会话的题目与作答（题面实时读库，改题后回看显示最新内容）；考试结果读 `snapshot_json`，题目被改动或删除时顶部提示“以下为作答时内容”。

**自动保存**

- 考试：选择变化 300 ms 防抖保存；顶栏状态实时反馈；失败自动重试 3 次并提示。
- 练习：提交即保存；弱网/引擎异常时保留本地状态，提示“保存失败，点击重试”。

**计时**

- 以 `remaining_sec` 初始化本地倒计时，每 30 s 或用 `visibilitychange` 恢复时校准。
- 到 0 自动调用提交；提交失败则重试并展示阻塞弹窗，禁止继续答题。
- 关闭窗口前若考试进行中，`onCloseRequested` 二次确认（可复用 Tauri 窗口事件）。

**图片**

- 题干图片最大宽度 100%，最大高度 420 px；选项图片缩略；点击使用 Ant `Image` 预览，支持缩放与切换。
- 加载失败显示“图片缺失：<filename>”，提供重新上传入口（编辑模式）。

### 8.5 状态管理

- `useAuthStore`：沿用现有结构，改为本机静默登录；token 存 `quiz-token`，启动时校验 `/auth/me`。
- `useAppStore`：沿用现有引擎健康检查，展示顶栏状态角标。
- `useAttemptStore`（新建）：
  - `summary`：id、mode、status、total、answeredSeqs、markedSeqs、lastSeq、remainingSec、truncated；
  - `batches`：`Map<seq, Question>` 缓存，按需加载；
  - `answers`：`Map<questionId, string[]>` 本地即时状态；
  - `currentSeq`、`saving`、`saveError`；

- 偏好设置：默认数量/乱序来自 `GET /settings`，弹窗内可临时覆盖。

### 8.6 错误、空状态与加载

- 引擎不可用：全屏提示“本地服务未启动”，展示当前 `getApiBase()` 与 `/health` 地址、重试按钮；诊断抽屉可看日志。
- 题库为空：插画 + “导入题目/新建题目”双按钮。
- 题目图片缺失：占位卡片，不阻塞答题。
- 导入 0 行成功：结果页展示错误报告下载与首批错误。
- 列映射缺失/冲突：映射步骤高亮缺失字段与重复列，提交按钮禁用并说明原因。
- 撤销批次：确认弹窗写明“将移除本批次 N 道题；已手动编辑的 M 道会保留；历史成绩不受影响”。

### 9.2 Rust 主进程改造点

基于 `智能运维系统/src-tauri/src/lib.rs` 改造（原文件已有托盘、关闭行为、`engine_base_url`、`set_window_size`，缺 sidecar 拉起）：

| 项 | 改动 |
| --- | --- |
| sidecar 拉起 | 用 `tauri-plugin-shell` 的 `sidecar("engine")` 启动；引擎作为 `externalBin` 随安装包分发，不再内嵌字节或释放到 `bin/` |
| 启动参数 | `--host 127.0.0.1 --port 0 --data-dir <app_data_dir>`；`CREATE_NO_WINDOW`；通过环境变量 `QUIZBOX_SHUTDOWN_TOKEN` 注入一次性关闭令牌 |
| 端口获取 | 捕获 sidecar stdout，读取 `ENGINE_PORT=<n>` 并写入 `EngineState`；最多等 10 s |
| 地址下发 | 命令签名保持 `engine_base_url() -> String`，内部改为读 `EngineState`（原实现读环境变量 `ENGINE_PORT`），返回 `http://127.0.0.1:<port>/api/v1`；浏览器开发模式由 `request.ts` 回退 `http://127.0.0.1:54310/api/v1` |
| 窗口显示 | 保留 `set_window_size`：主界面 1200×800、可缩放，调用时 `show()` + `set_focus()`；删除登录页 900×520 分支；按当前显示器物理可用空间钳制窗口与最小尺寸，避免高 DPI / 小屏下超出屏幕 |
| 关闭行为 | 保留 `set_close_behavior`（minimize/exit）与 `CloseRequested` 拦截；考试进行中的二次确认由前端负责 |
| 就绪检测 | 端口读取成功即视为就绪；超时也显示窗口，由前端 `/health` 重试并展示“引擎启动失败 + 诊断” |
| 启动失败 | spawn 失败不要直接中止应用；记录错误、显示窗口并让前端展示可诊断的错误页 |
| 托盘 | 沿用源项目：菜单“打开主界面 / 退出程序”；左键恢复；提示文案“题鸣” |
| 单实例 | 必须作为第一个插件注册 `tauri-plugin-single-instance`；回调内调用 `show_main_window(app)` 激活已有窗口 |
| 正常关闭 | 窗口关闭/托盘退出时先调 `POST /system/shutdown`（带令牌），最多等 3 s，再 kill + wait；超时记录日志并强制结束 |
| 恢复标记 | 启动引擎前检查 `restore.pending.json`：校验备份、调用 `engine --verify-db <临时库>`、生成 pre-restore 备份、原子替换数据，失败则保留原数据并写 `restore.error.log` |
| 日志 | 转发引擎 stdout/stderr 到宿主控制台，便于开发排查 |

`capabilities/default.json` 删除 `autostart:*`，保留 `core:window:*`（minimize/toggle-maximize/close/hide/start-dragging）与 `shell:allow-spawn/execute`。`Cargo.toml` 删除 `tauri-plugin-autostart`，增加 `tauri-plugin-single-instance`，保留 `tauri-plugin-shell`。

### 9.3 构建脚本

`build-engine.ps1`（新建）：

```powershell
$ErrorActionPreference = "Stop"
$root = $PSScriptRoot
$ver = (Get-Content (Join-Path $root "src-tauri\tauri.conf.json") -Raw | ConvertFrom-Json).version
$binDir = Join-Path $root "src-tauri\binaries"
New-Item -ItemType Directory -Force -Path $binDir | Out-Null

$env:CGO_ENABLED = "0"
$env:GOPROXY = "https://goproxy.cn,direct"
Push-Location (Join-Path $root "engine")
try {
  go build -trimpath -ldflags "-s -w -X main.version=$ver" `
    -o (Join-Path $binDir "engine-x86_64-pc-windows-msvc.exe") ./cmd/engine
  if ($LASTEXITCODE -ne 0) { throw "go build failed: $LASTEXITCODE" }
} finally {
  Pop-Location
}
```

`build.ps1`：

```powershell
$ErrorActionPreference = "Stop"
Set-Location $PSScriptRoot
powershell -ExecutionPolicy Bypass -File .\build-engine.ps1
pnpm install --frozen-lockfile
pnpm tauri build        # beforeBuildCommand 会执行 pnpm build（vue-tsc + vite）
```

产物：

- 安装包 `src-tauri/target/release/bundle/nsis/题鸣_0.1.0_x64-setup.exe`（内含 sidecar）。
- 免安装版需同时保留 `target/release/题鸣.exe` 与 `target/release/engine-x86_64-pc-windows-msvc.exe`，两者放在同一目录才能启动；单独拷走 `题鸣.exe` 会因找不到 sidecar 而失败。

代码签名（正式分发必做）：

- 在 `bundle.windows` 配置 `certificateThumbprint`、`digestAlgorithm: "sha256"`、`timestampUrl`（Tauri 会在打包时签名）；或打包后用 `signtool sign /fd sha256 /tr <时间戳地址> /td sha256` 手动签。
- 发布前用 `signtool verify /pa /v` 校验安装包与主程序；未签名包仅限内测，需在说明中标注 SmartScreen 提示。
- 构建使用 `pnpm install --frozen-lockfile` 与基线 Node 版本，避免依赖漂移；产物记录基线提交 SHA。

### 9.4 开发工作流

```powershell
# 终端 1：引擎（数据目录指到项目内 data/）
cd engine
go run ./cmd/engine --data-dir ..\data --port 54310

# 终端 2：前端热更新
pnpm dev                 # http://localhost:54311，/api 代理到 54310

# 可选：桌面窗口联调（Tauri 会自行拉起 sidecar，先停掉终端 1）
pnpm tauri dev
```

`pnpm tauri dev` 会执行 `beforeDevCommand`（`pnpm dev`）并由宿主启动 sidecar（`--port 0` 动态端口），不要与终端 1 的固定端口引擎同时运行。浏览器调试时 `initApiBase()` 取不到 `engine_base_url`，回退 `/api/v1` 交给 Vite 代理，因此终端 1 必须处于运行状态。

### 9.5 版本与升级

- 版本号三处同步：`package.json`、`src-tauri/tauri.conf.json`、Go 构建参数 `-X main.version`（引擎 `/health` 返回同一版本号）。
- 数据库迁移由引擎启动时执行；升级前自动备份到 `backups/pre-migrate-<version>.zip`。
- 引擎产物固定写到 `src-tauri/binaries/engine-x86_64-pc-windows-msvc.exe`；替换后必须重新执行 `pnpm tauri build`（安装包内容在打包时固化），直接覆盖安装目录里的 sidecar 只对免安装版有效。
- 安装包未签名时 Windows SmartScreen 会提示“未知发布者”；正式分发建议代码签名。

## 10. 安全、性能与运维

### 10.1 安全

| 项 | 措施 |
| --- | --- |
| 监听范围 | 桌面端 sidecar 绑 `0.0.0.0` 以支持外联考试；`/api/v1/*` 全部要求本机会话 token，对外只开放 `/e/{token}` 与 `/api/public/*`（需考试 token 或答题凭证）。手动运行引擎默认仍为 `127.0.0.1` |
| 鉴权 | 会话 token 存 `sessions` 表（7 天过期，重启不失效）；前端放 localStorage `quiz-token`，每次请求带 `X-Token`，不设 refresh 接口。桌面端只在 `--desktop` 且来源为回环时允许 `local` 空密码静默登录；网页版走用户名密码登录 + 图形验证码 |
| 注册 | 图形验证码（5 分钟有效、一次性）+ 按 IP 限流 5 次 / 10 分钟；用户名 2–20 位，密码 8–72 位；首个注册账号自动成为管理员，`local` 为保留名 |
| 限流 | 登录 10 次 / 5 分钟 / IP，注册 5 次 / 10 分钟 / IP，AI 提问 20 次 / 5 分钟 / 用户；超限返回 429 |
| CORS | 只回显白名单来源 `tauri://localhost`、`http://tauri.localhost`、`https://tauri.localhost`、`http://localhost:54311`、`http://127.0.0.1:54311`；不带 `Allow-Credentials`，未匹配来源不加 CORS 头（原项目用 `*`，这里收紧） |
| 会话失效 | 引擎返回 401 后前端清 token → 静默重登 → 重放一次；仍失败提示“本地服务连接失败”，不跳登录页 |
| XSS | 题干/选项/解析按纯文本渲染，禁用 `v-html`；图片只允许位图 |
| 上传 | 限制大小、行数、图片数量；按文件头识别 MIME；文件名只用 SHA-256 + 扩展名 |
| 路径 | 图片只接受 64 位十六进制文件名 + png/jpg/jpeg/webp/gif 扩展名；禁止 `..` 与绝对路径 |
| SQL | 全部参数化查询；排序字段白名单 |
| 导入 | 不计算公式、不执行 HTML；CSV 公式前缀按文本处理；ZIP 包拒绝路径穿越并限制解压总量 |
| 关闭接口 | `POST /system/shutdown` 校验 `X-Shutdown-Token`（常数时间比较）；引擎未拿到令牌时接口直接 404，服务端部署天然不暴露；令牌不落日志 |
| 外联考试 | 考试密码 PBKDF2 加盐、12 万次迭代；考试/答题 token 均为 32 字节随机数；`UNIQUE(exam_id,student_no)` 防重复交卷；公开接口不返回他人成绩与题库原文；题干/选项按纯文本渲染 |
| 防火墙 | 提供「允许局域网访问」按钮，经 UAC 授权后仅为引擎与主程序添加入站规则，不为端口全局放行 |
| 恢复 | 校验备份 manifest 与文件 SHA-256；解压拒绝绝对路径与 `..`；恢复前自动备份当前数据；版本不兼容直接拒绝 |
| 数据 | 备份 zip 只写数据目录，包含做题记录，提示用户妥善保管；不上传任何第三方 |

### 10.2 性能

- SQLite：WAL、`busy_timeout=5000`、单写连接；批量导入 500 行/事务；统计查询走索引。
- 题目列表分页 20 条；题干列表只取前 200 字预览，详情再取全文。
- 答题会话分批 50 题；前端缓存已加载批次，预取下一批。
- 组卷写入按 500 行/事务提交，5,000 题会话不长时间独占写锁；答题卡超过 200 题启用虚拟滚动，DOM 数量与题量脱钩。
- 快照约 0.5–2 KB/题，5 万条答题记录约几十 MB，可接受；结果页只按批读取快照，不整卷加载。
- 图片懒加载；列表缩略图使用同一原图（本地文件，开销可接受），必要时后续生成缩略图。
- 自动备份用 `VACUUM INTO` 快照，不阻塞读取；每日首启在迁移后、接客前完成，导入前备份在异步任务开始时执行。
- 静态资源：`--web-dir` 由引擎托管，文本资源按 `Accept-Encoding` 现场 gzip（`BestSpeed` + `sync.Pool`），`assets/*` 长缓存 immutable、`index.html` no-cache + ETag/304、未压缩分支交 `http.ServeContent` 保留 206；首屏传输量由 1.63 MB 降到约 600 KB，配合 `manualChunks` 拆包实现并行下载。
- 首次启动：sidecar 解压/启动 + 迁移，目标 3 s 内进入界面；导入进度异步展示。

### 10.3 日志

- 引擎日志写 `data/logs/engine-YYYYMMDD.log`，保留 14 天；同时输出 stdout 供 Tauri 转发。
- 记录：启动参数、迁移版本、端口、每类请求耗时（>500 ms 警告）、导入任务摘要、panic 堆栈。
- 前端诊断抽屉读 `GET /api/v1/system/logs`，返回内存环形缓冲最近 400 行 + 版本/数据目录/端口；全宽显示、等宽字体、支持复制。
- 500 统一返回 `50000` + “内部错误”，详细原因写引擎日志；排障时按时间点检索 `internal error:` 行。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 复制源项目带进无关模块（巡检/报告/终端） | 依赖体积、路由混乱 | 按 3.2 清单删除视图与 `api/*`，构建后用 `vue-tsc` 与体积报告核对；不保留未引用的依赖 |
| 前端与引擎信封不一致 | 全站请求失败 | 固定 `{code:0}` + `X-Token`；集成测试覆盖登录、列表、交卷 |
| sidecar 未随包分发或文件名不匹配 | 应用启动即失败 | `externalBin` 使用带 target triple 的文件名；构建脚本先产引擎再打包；验收检查安装目录含 `engine-*.exe` |
| Excel 格式千奇百怪 | 导入失败/脏数据 | 固定模板 + 预览 + 行级错误 + 别名兼容 + 样例文件 |
| CSV 中文乱码 | 题干乱码 | BOM → UTF-8 → GBK 依次尝试；失败明确报错 |
| 图片文件名不匹配 | 图片缺失 | 导入警告、占位图、编辑页补传；文档强调文件名规则 |
| 端口冲突/重复启动 | 引擎起不来 | 单实例插件、端口健康校验、明确错误页 |
| WebView 首次加载早于引擎就绪 | 白屏/请求失败 | Tauri 等端口就绪再显示窗口 + 前端重试 |
| 杀进程导致数据库损坏 | 数据丢失 | WAL + 启动恢复 + 定时快照 + 升级前备份 |
| 大题库一次性下发 | 卡顿/内存高 | 分批拉题、分页列表、图片懒加载 |
| 本地 token 被同机其他程序读取 | 数据被改 | 定位为单机个人工具；如提升安全要求，改为系统凭据存储 + 每次启动令牌 |
| 未签名安装包被 SmartScreen 拦截 | 分发受阻 | 文档说明；正式发布做代码签名 |
| 关闭窗口误退出考试 | 进度丢失 | 答案实时落库；关闭前确认；重开可恢复 |

## 附录 A 启动参数与端口

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 监听地址；桌面端绑 `0.0.0.0` 以支持外联考试 |
| `--port` | `54310` | HTTP 端口；`0` 表示动态分配并打印 `ENGINE_PORT=<n>`，桌面端固定用 0 |
| `--data-dir` | `data` | 数据目录；Tauri 传 `%APPDATA%\com.quizbox.desktop` |
| `--desktop` | `false` | 桌面模式：允许回环来源用 `local` + 空密码静默登录。**反向代理部署时不要加** |
| `--web-dir` | 空 | 前端构建产物目录；设置后由引擎托管网页版（含 gzip 与缓存头） |
| `--verify-db <path>` | — | 校验指定数据库完整性后退出（恢复流程使用） |
| `--version` | — | 打印版本并退出 |

环境变量：`QUIZBOX_SHUTDOWN_TOKEN`（宿主注入，`POST /system/shutdown` 校验）；`ENGINE_PORT` 由引擎写入 stdout 供宿主解析，不是入参。

| 用途 | 端口 |
| --- | --- |
| Go 引擎（开发期固定） | 54310 |
| 前端开发服务器 | 54311 |
| 打包后引擎 | 系统分配（`--port 0`） |
