# 网页版服务端部署

Qecho（题鸣）的同一套 Go 引擎既可作为桌面端的本地 sidecar，也可直接部署到服务器，用浏览器访问。
网页版与桌面端共用全部接口、数据库结构与权限模型。

## 1. 模式差异

| | 桌面端 | 网页版服务端 |
| --- | --- | --- |
| 启动方式 | Tauri 自动拉起 sidecar | 手动 / systemd 启动 |
| 参数 | `--desktop`，动态端口 | 不带 `--desktop`，固定端口 |
| 登录 | 回环地址可用 `local` 空密码 | 用户名 + 密码，需先注册 |
| 前端 | 壳内加载 | `--web-dir` 指向 `dist/` 由引擎托管 |

`--desktop` 仅允许来自回环地址的 `local/空密码` 登录。**反向代理部署时不要加 `--desktop`**，
否则代理转发的本机请求也可能被当作本机登录。

## 2. 构建

```powershell
# 前端静态文件 → dist/
pnpm install --frozen-lockfile
pnpm build

# 引擎：版本号自动从 tauri.conf.json 注入，产物在 dist-server/
./build-server.sh
```

> 不要手写 `go build` 而不带 `-X main.version`，否则「关于」页和 `/health` 会显示 `dev`，客户端也无法比对版本。

`build-server.sh` 默认 `GOOS=linux GOARCH=amd64`，也可传输出路径：
`./build-server.sh /tmp/quizbox-engine`。

## 3. 启动

```bash
./quizbox-engine \
  --host 0.0.0.0 \
  --port 54310 \
  --data-dir /var/lib/quizbox \
  --web-dir /opt/quizbox/dist
```

- `--data-dir`：SQLite、日志、备份所在目录，需可写。
- `--web-dir`：前端构建产物目录；设置后由引擎托管网页版（`/`、`/e/<token>`）。
- `--port 0`：动态端口（桌面端用法，服务端不要用）。

### 3.1 一键安装（推荐）

发行版里附带服务端专用的包 `Qecho-<版本>-web-linux-amd64.tar.gz`
（[下载页](https://gitee.com/qqtq/qecho/releases)），内含引擎、`dist/` 与安装脚本：

```bash
tar xzf Qecho-0.2.6-web-linux-amd64.tar.gz
cd quizbox-web-0.2.6
sudo ./install.sh                                  # 默认 0.0.0.0:80
sudo ./install.sh --port 3000                      # 换端口
sudo ./install.sh --addr 127.0.0.1 --port 54310    # 只监听本机，交给 Nginx
```

脚本会建 `qecho` 系统用户、装到 `/opt/quizbox`、准备 `/var/lib/quizbox`、写入
`/etc/systemd/system/qecho.service` 并启动自检（首页非 200 时打印日志并退出）。

- 引擎是 `CGO_ENABLED=0` 静态链接，目标机不需要 Go、Node、glibc 开发库或 libGL，
  任意 x86_64 Linux 均可（Ubuntu / Debian / Rocky / OpenCloudOS / 麒麟 / 统信）。
- 80 端口靠 systemd 的 `AmbientCapabilities=CAP_NET_BIND_SERVICE` 授权，无需 root 运行。
- 可重复执行：升级时把新的 `quizbox-engine` 与 `dist/` 覆盖进包目录后重跑，数据目录不动。
- 已开启 SELinux 的 RHEL 系会自动给二进制打 `bin_t` 标签。

### 3.2 静态资源托管行为

设置 `--web-dir` 后，前端由引擎自身托管，行为约定如下（实现见 `engine/internal/api/web.go`）：

| 资源 | 压缩 | 响应头 | 备注 |
| --- | --- | --- | --- |
| `index.html` 与 SPA 回退 | gzip | `Cache-Control: no-cache`、`ETag` | 配合 `If-None-Match` 返回 `304`，刷新即拿到新版本 |
| `assets/*` | gzip | `Cache-Control: public, max-age=31536000, immutable` | 文件名含内容哈希，可放心长期缓存 |
| 图片 / 字体 | 原样 | 同上 | 已压缩格式不做二次压缩 |

- 压缩按请求头 `Accept-Encoding: gzip` 现场进行，服务端不落盘预压缩文件；首屏 JS 由 1.63 MB 降到约 600 KB。
- 未压缩分支由 `http.ServeContent` 处理，支持 `206` 断点续传与 `If-Range`；压缩分支返回 `Accept-Ranges: none`，浏览器不会尝试按字节续传。
- 未命中路径：不带扩展名回退 `index.html`（hash 路由），带扩展名返回 `404`。

因此**不需要**再在前面挂一个自己处理静态文件的 Nginx `root`——静态资源与 API 同源，多一层反而会丢缓存头。

首次启动后打开站点，**第一个注册的账号会自动成为管理员**，之后的注册用户均为普通用户。
建议部署完成后立即注册管理员，再关闭公开注册入口或控制访问。

### 3.3 自定义参与者页（e.html）

考生用手机打开的答题页（`/e/<token>`）是引擎内嵌的单文件 HTML。0.2.5 起支持用外部文件覆盖它，**改文案、改版式不必重编引擎、不必重新发版**。

读取顺序（实现见 `engine/internal/api/page.go`）：

1. 环境变量 `QUIZBOX_PAGE` 指向的文件；
2. 数据目录下的 `e.html`（如 `/var/lib/quizbox/e.html`）；
3. 编译时内嵌的版本（兜底）。

```bash
# 把改好的 e.html 放到数据目录，刷新参与者页即生效
sudo install -m 644 -o quizbox -g quizbox ./e.html /var/lib/quizbox/e.html
```

- 响应头为 `Cache-Control: no-store`，改完直接在考生手机上刷新，无需重启服务；
- 想撤回就删除该文件，自动回落内嵌版本；
- 文件不存在、读不出来或为空时同样回落内嵌版本，不会白屏；
- 只影响参与者页，管理后台前端仍在 `--web-dir` 指定的目录里；
- 桌面版同理：文件放到各自的数据目录即可（Windows 为 `%APPDATA%\com.quizbox.desktop`）。

## 4. systemd 示例

`/etc/systemd/system/quizbox.service`：

```ini
[Unit]
Description=Quizbox engine
After=network.target

[Service]
Type=simple
User=quizbox
Group=quizbox
WorkingDirectory=/opt/quizbox
ExecStart=/opt/quizbox/quizbox-engine --host 127.0.0.1 --port 54310 --data-dir /var/lib/quizbox --web-dir /opt/quizbox/dist
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /usr/sbin/nologin quizbox
sudo mkdir -p /var/lib/quizbox && sudo chown -R quizbox:quizbox /var/lib/quizbox
sudo systemctl daemon-reload
sudo systemctl enable --now quizbox
```

监听 `127.0.0.1` 时由反向代理对外，更安全；局域网直连可监听 `0.0.0.0`。

## 5. HTTPS 反向代理（Nginx）

```nginx
server {
    listen 443 ssl http2;
    server_name quiz.example.com;

    ssl_certificate     /etc/letsencrypt/live/quiz.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/quiz.example.com/privkey.pem;

    client_max_body_size 50m;   # 题库导入上传

    location / {
        proxy_pass http://127.0.0.1:54310;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}

server {
    listen 80;
    server_name quiz.example.com;
    return 301 https://$host$request_uri;
}
```

引擎会读取来自回环地址的 `X-Forwarded-For` 作为客户端 IP，用于登录限流。

外联考试链接按当前访问域名生成（`https://quiz.example.com/e/<token>`），参与者可直接用手机打开。

反向代理注意事项：

- 引擎已对文本资源做 gzip，Nginx **不必再开** `gzip on`；上游响应带 `Content-Encoding` 时 Nginx 不会重复压缩。
- 若希望统一由 Nginx 压缩，加 `proxy_set_header Accept-Encoding "";` 让引擎直出未压缩内容，此时 `Range`／`206` 仍然可用（引擎会交给 `http.ServeContent`）。
- Nginx 默认透传 `Range`、`If-None-Match`、`Cache-Control`、`ETag`，**不要**用 `proxy_hide_header` 屏蔽，否则会退化成每次整包重下。

## 6. 数据与备份

- 数据库：`<data-dir>/quiz.db`（WAL 模式，另有 `quiz.db-wal`、`quiz.db-shm`）。
- 日志：`<data-dir>/logs/engine-YYYYMMDD.log`。
- 备份需同时包含 db + wal + shm，或使用 SQLite 在线备份：

```bash
sqlite3 /var/lib/quizbox/quiz.db ".backup '/var/backups/quizbox-$(date +%F).db'"
```

- 完整性校验：`./quizbox-engine --verify-db /var/lib/quizbox/quiz.db`，输出 `ok: user_version=N`。
- 升级替换二进制后直接重启即可：引擎启动时按 `user_version` 自动执行内嵌迁移，迁移前会把旧库备份到 `<data-dir>/backups/pre-migrate-<version>.zip`（备份失败则中止迁移，旧版本仍可启动）。

## 7. 安全清单

- 不要对公网暴露 `--desktop` 模式。
- 登录接口按 IP 限流（10 次 / 5 分钟），注册按 IP 限流（5 次 / 10 分钟）；注册需通过图片验证码（5 分钟有效、一次性）。公网部署仍建议尽快创建管理员账号。
- 会话 token 存在浏览器 `localStorage`，通过 HTTPS 访问以免被中间人截获。
- 引擎自身不做 TLS 终止，请始终置于 HTTPS 反向代理之后。
- `X-Shutdown-Token` 仅在桌面端注入；服务端未设置时关闭接口返回 404。
- 普通用户默认不能新建题库、不能导出/导入题库，由管理员在侧边栏「用户管理」中逐个授予；题库共享支持「共享给指定用户（只读/可编辑）」与「所有登录用户可读」两种范围，管理员始终能读写全部题库。
