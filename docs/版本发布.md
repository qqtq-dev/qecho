# 版本更新与发布

## 1. 仓库与清单

源码、版本清单、安装包都放在同一个仓库，不再拆发布仓：

| 仓库 | 可见性 | 内容 |
| --- | --- | --- |
| `gitee.com/qqtq/qecho` | **公开** | 全部源码 + `release/version.json` + 安装包（Releases），**主仓库** |
| `github.com/qqtq-dev/qecho` | **公开** | 与主仓库同内容，**镜像**；Releases 挂同一批安装包 |

客户端启动后由引擎**同时**请求两个清单地址（并发，单个超时不影响另一个），与自身版本比对，**取版本号更高的那份**；发现新版本时在顶栏铃铛提示。所以两端谁先合并都能提示到：

```
https://raw.githubusercontent.com/qqtq-dev/qecho/main/release/version.json   # GitHub 镜像
https://gitee.com/qqtq/qecho/raw/main/release/version.json                   # Gitee 主仓
```

两份清单指向同一份文件（`release/version.json`），内容必须一致；只合并了一端时，另一端会稍晚才提示，不影响判定。

> 旧的 `qecho-releases` 发布仓已停用：版本清单、安装包、界面截图全部收进主仓库，Gitee 与 GitHub 各只保留一个仓库。
>
> **确认发布版没跟上**：已安装的 0.2.6 是改动前编译的，二进制里只有旧地址 `gitee.com/qqtq/qecho-releases/raw/master/version.json`。想让这批客户端也能收到提醒，发 0.2.7 时顺手把该仓库的 `version.json` 也更新一次；0.2.7 起不再需要这一步。

## 2. 发版步骤

1. **改版本号**（两处必须一致）：
   - `package.json` 的 `version`
   - `src-tauri/tauri.conf.json` 的 `version`

2. **构建**：
   ```bash
   pnpm build
   ./build-server.sh          # 服务端 Linux 二进制，版本自动注入
   ./build-engine.ps1         # 桌面端 sidecar，同样自动注入
   ```

3. **改版本清单**：编辑 `release/version.json`，`version` 填新版本号，`notes` 写两三句更新摘要（铃铛里最多显示三行，建议 40 字内），`url` 指版本说明页，`downloadUrl` 指下载页。

4. **提交推送主仓**：
   ```bash
   git add release/version.json
   git commit -m "release: v0.3.0"
   git push origin main
   ```
   清单随源码一起走，GitHub 镜像同步后，GitHub 侧的清单地址也就生效了。

5. **上传安装包**：在主仓库「发行版 / Releases」里新建标签（如 `v0.3.0`），标题与标签同名，正文写下表：

   | 平台 | 文件 | 来源 |
   | --- | --- | --- |
   | Windows 安装版 | `Qecho_<版本>_x64-setup.exe` | `src-tauri/target/release/bundle/nsis/` |
   | Windows 免安装版 | `Qecho-<版本>-x64-portable.zip` | `build-portable.ps1` 产出 |
   | Debian / Ubuntu（glibc ≥ 2.39） | `Qecho_<版本>_amd64.deb` | `scripts/linux/build-in-container.sh deb` |
   | Fedora / RHEL 10（glibc ≥ 2.39） | `Qecho-<版本>-1.x86_64.rpm` | 同上，参数 `rpm` |
   | 通用 Linux（glibc ≥ 2.39） | `Qecho-<版本>-x86_64.AppImage` | 同上，参数 `appimage`，产物在仓库根目录 |
   | 服务端网页版 | `Qecho-<版本>-web-linux-amd64.tar.gz` | `scripts/pack-web.sh` |
   | 校验值 | `SHA256SUMS.txt` | 六个包一起算，放最后传 |

   网页版包不必关注打包机的文件权限：`pack-web.sh` 会在归档内部把
   `quizbox-engine` 与 `install.sh` 的权限改成 755（`scripts/tar-mode.py`），
   改完回读校验，不通过直接失败——Windows 上给无扩展名的 ELF 设执行位是静默失效的。

   **走接口传**（需要私人令牌，勾 `projects` 权限）：

   ```bash
   export GITEE_TOKEN=<私人令牌>
   python scripts/publish-release.py 0.3.0        # 建发行版 + 传包 + 算校验值
   ```

   **走网页传**：仓库 →「发行版」→「新建发行版」，标签填 `v0.3.0`，把上表文件逐个拖进去。

   注意发行版页面下方的 `Source code (zip / tar.gz)` 是 Gitee 按标签自动生成的，内容是当前提交的源码快照，删不掉也不用管，与安装包无关。

6. **验证**：
   ```bash
   curl -s https://gitee.com/qqtq/qecho/raw/main/release/version.json
   ```
   客户端点开铃铛会强制刷新，不用等缓存过期。

## 3. version.json 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 最新版本号，支持 `0.3.0` 或 `v0.3.0` |
| `publishedAt` | 否 | 发布日期，`YYYY-MM-DD`，当前界面不展示，留档用 |
| `notes` | 否 | 更新摘要，界面最多显示三行 |
| `url` | 否 | 版本说明页，缺省用仓库首页 |
| `downloadUrl` | 否 | 下载页，缺省用 `url` |
| `force` | 否 | 置 `true` 表示重要更新，界面会标注 |

## 4. 客户端行为

- 引擎接口：`GET /api/v1/update/check`，可加 `?force=1` 绕过缓存
- 缓存：请求成功缓存 30 分钟，失败缓存 5 分钟；用户点开铃铛时强制刷新
- 版本比较：按数字段逐位比较，`0.10.0 > 0.9.0`；`dev` 这类无法解析的版本一律不提示
- 拉取失败（断网、仓库临时不可用）时静默处理，不弹错误、不影响使用
- 点「查看更新」调系统默认浏览器打开，桌面端走壳层命令 `open_external`，只放行 http/https

## 5. 排错

**关于页显示 `dev`**：二进制编译时没带 `-X main.version`。用 `build-server.sh` / `build-engine.ps1` 重新编译，版本号会自动从 `tauri.conf.json` 读取。

**接口返回 `ok: false`**：说明两个地址都拉不到清单。依次检查仓库是否可匿名访问（若误设为私有会 404）、分支是不是 `main`、`release/version.json` 是否在预期路径。

**想换清单地址**（例如改放自有服务器）：启动引擎时设环境变量 `QUIZBOX_UPDATE_URL`，不用改代码重新编译。

## 6. 不必发版的改动

参与者页（考生手机打开的那个 `/e/<token>` 页面）的文案与版式**不需要走发版流程**。0.2.5 起引擎按「`QUIZBOX_PAGE` 环境变量 → 数据目录下 `e.html` → 编译时内嵌版本」的顺序取页面：

```bash
# 服务器版：改完立刻生效，删掉文件即回落内嵌版本
sudo install -m 644 -o quizbox -g quizbox ./e.html /var/lib/quizbox/e.html
```

其余改动（前端 `src/`、引擎 `engine/` 下的 Go 代码、`tauri.conf.json` 配置）仍需按第 2 节完整发版，安装包里是编译产物，拷文件过去没用。
